GPT-6.1 Terra Use Cases: What Real Workloads Actually Cost

Terra's price list ($1 input / $0.05 cached / $5 output per million) only means something once it meets a real workload. Below are five concrete jobs teams run on Terra, each with the monthly arithmetic worked out. Run your own numbers in the free cost calculator, or follow the step-by-step estimation guide.

1. Customer support chatbot

The setup. A SaaS helpdesk bot answers 200,000 conversations a month. Each conversation averages 3,000 input tokens (system prompt plus history) and 400 output tokens. The system prompt and help-center context repeat across nearly every session, so about 70% of input lands as cached reads.

The math. Fresh input 180M × $1.00 = $180; cached input 420M × $0.05 = $21; output 80M × $5.00 = $400 — roughly $600/month at full volume, or about $22/month for a smaller bot doing 7,500 conversations. The same workload on GPT-5.6 Terra ran about 2.7× more, because cached reads were $0.20 instead of $0.05.

The lever. Cache hit rate. Moving from 50% to 90% cached input is worth more than any other optimization on this workload.

2. Invoice and document processing

The setup. An accounting tool extracts vendor, amounts, tax IDs and line items from 50,000 invoices a month. Each document is about 2,000 input tokens; the extraction schema returns roughly 300 output tokens. Nothing is latency-sensitive, so everything runs in Batch mode.

The math. Input 100M × $0.50 (Batch) = $50; output 15M × $2.50 (Batch) = $37.50 — about $88/month. Short documents never approach the 272K threshold, so the surcharge never applies.

The lever. Batch mode halves every rate. If your pipeline can wait minutes instead of seconds, this is the cheapest serious document extraction available in the GPT-6 family.

3. RAG assistant over a company knowledge base

The setup. An internal assistant answers employee questions over retrieved documents: 30,000 questions a month, each carrying about 8,000 tokens of retrieved context and producing a 600-token answer.

The math. Input 240M × $1.00 = $240; output 18M × $5.00 = $90 — about $330/month. Retrieved chunks repeat across similar questions, so a healthy cache trims the input line further.

The lever. Watch prompt size. If retrieval starts stuffing whole manuals into single requests past 272K tokens, the entire request bills at double input — chunk discipline is a billing feature, not just a quality one.

4. Long-session agent (computer use / RPA)

The setup. A browser agent works through multi-step tasks — checking dashboards, reconciling records — in sessions of around 10M input tokens at a 97% cache hit rate, with 200K output tokens per session.

The math. Per session: fresh input 0.3M × $1.00 = $0.30; cached 9.7M × $0.05 = $0.49; output 0.2M × $5.00 = $1.00 — about $1.79 per session, versus $4.94 for the identical session on GPT-5.6 Terra.

The lever. Session length works for you here, not against you: the longer the session, the higher the cached share — as long as no single request crosses 272K fresh tokens.

5. Overnight batch pipeline (classification and enrichment)

The setup. A data team classifies and enriches 2 million short records nightly — tickets, listings, leads. Each record is about 500 input tokens and 100 output tokens, all processed in Batch/Flex mode.

The math. Per night: input 1,000M × $0.50 = $500; output 200M × $2.50 = $500 — about $1,000/night at that scale, scaling linearly down: a tenth of the volume is a tenth of the price.

The lever. Model routing. Shallow records (tagging, sentiment, dedup keys) belong on GPT-6 Luna at one tenth of Terra's price; send only ambiguous records up to Terra and the nightly bill drops by most of its size.

FAQ

What is a realistic monthly GPT-6.1 Terra budget for a small support chatbot?

Around $20-50 a month. A bot handling 200,000 conversations at roughly 3K input and 400 output tokens each lands near $22 on Terra when the system prompt is cached; the same bot cost roughly $65 on GPT-5.6 Terra.

Which GPT-6.1 tier fits document processing like invoices?

Terra for extraction quality, run in Batch mode to halve the rates. Fields are short and structured, so most documents never touch the 272K surcharge. Luna can undercut Terra tenfold when the documents are simple forms.

When is GPT-6 Luna a better choice than Terra?

When the task is high-volume and shallow: FAQ deflection, tagging, first-pass classification. Luna costs one tenth of Terra, so routing the easy 80% of traffic there and escalating the rest to Terra cuts most of the bill.

When should I pay for GPT-6.1 Sol instead of Terra?

When a wrong answer is expensive: legal or financial reasoning, complex multi-step planning, code review of critical paths. Sol is exactly twice Terra's price, so most teams reserve it for the hardest slice of traffic rather than the whole workload.
